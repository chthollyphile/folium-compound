# 小窗拖边修复 / Remote Window Edge

![preview](preview.jpg)

Folia 的远程控制小窗是**虚大了一圈**的：窗口 602 × 184，而放歌时看得见的内容只有右边
420 × 176，剩下 182 px 完全透明，却照样算在窗口里。播放器按整个窗口限制拖动，于是这圈虚的
部分成了小窗真正的边界——看得见的卡片被顶在离屏幕左边缘 178 px 处，再也拖不动。
这个模组把边界换成按可见卡片算：虚的那一圈不再算数，小窗能贴到、并越过屏幕左边缘。

- 模组 id：`remote-window-edge`
- 版本：1.0.0
- 要求：Folia 0.7.21 及以上（`folia: ">=0.7.21 <0.8.0"`）
- 权限：`filesystem.data`（只用来存一个 0–278 的整数设置）
- 作者：Hyacinth（[@miaowu104-gif](https://github.com/miaowu104-gif)）

## 它做什么

远程控制小窗本身是固定 602 × 184 的透明无边框窗口，里面那张卡片 594 × 176 居中，分两半：

- 右边 **420 px** 是放歌时真正看到的部分；
- 左边 **174 px** 是空闲时放大封面用的（「展开封面」打开时），**放歌时完全透明**。

也就是说，放歌时窗口比看得见的内容**大了一圈**：左边 178 px（4 px 边距 + 174 px 空闲封面区）
加上右边 4 px 边距，一共 182 px 是虚的——屏幕上什么也看不见，却仍然是窗口的一部分。

播放器的拖动限制按**整个窗口**算，要求窗口左边缘落在屏幕内。于是这圈虚的部分成了小窗真正的
边界：可见卡片永远离屏幕左边缘至少 178 px，再往左拖不动。窗口没长那么宽，判定却按那么宽来
——这就是「虚大了一圈」的那一圈。

装上这个模组后，拖动按**可见卡片左边缘**判定，默认还允许再往左超出 178 px。虚的那一圈不再是
小窗的边界；指针从它上面经过时仍然穿到下面的窗口（这是播放器本来就有的行为，模组没有改）。

## 安装

1. 下载或克隆本仓库；
2. 把整个目录放进 `%APPDATA%\Folia\mods\remote-window-edge`（或把仓库打成 zip 拖进「设置 → 模组」）；
3. 打开「模组系统」开关，启用「小窗拖边修复」，在确认窗口里同意。

模组改的是主进程行为：启用或「重载」后立即生效，已经打开的小窗也会被接管。

## 使用

启用后直接拖动小窗即可：按住可见卡片往左拖，它会一直贴到屏幕左边缘，并能再越过 178 px。

「设置 → 模组 → 小窗拖边修复 → 小窗拖边」里有一条「左侧可超出（px）」：

| 值 | 效果 |
| --- | --- |
| 0 | 卡片最多贴到屏幕左边缘，不出屏 |
| 178（默认） | 卡片可以再往左超出 178 px，空判定区不再是边界 |
| 278（上限） | 窗口左边缘最多出屏 456 px，仍留 146 px 抓得住 |

命令面板里有「小窗拖边：状态」，显示设置值、主进程里生效的值和小窗数量。

## 工作原理（读什么、写什么）

宿主在 `electron/main.cjs` 里给远程控制窗口注册了一条 `will-move` 监听
（`keepRemoteControlCoverOnScreen`），它调用 `remoteControlWindowGeometry.cjs` 的
`clampRemoteControlWindowX`，把窗口左边缘夹在屏幕内。

模组的 `index.cjs` 跑在主进程，识别到那个窗口（标题 `Folia Remote`，或 602 × 184 的尺寸）后：

1. 移除那条 `will-move` 监听；
2. 换成自己的：锚点 = 窗口左边缘 + 178 + `overhang`，锚点还在某块屏上就放行，越界时夹到
   承载这块窗口最多的那块屏，下限是 `屏左边缘 − 178 − overhang`。

拖动时指针一定在窗口上，也就是卡片在用（空闲样式只在指针离开后才展开），所以拖动一律按卡片
判定，不需要知道当前是哪种样式。

读：

| 来源 | 用途 |
| --- | --- |
| `BrowserWindow.getAllWindows()` / `app.on("browser-window-created")` | 找到远程控制窗口 |
| `win.getTitle()` / `win.getSize()` | 认窗口，不改 |
| `screen.getAllDisplays()` | 拖动时读屏幕边界，算允许的 x |
| `api.storage.get("overhang")` | 读上次存的设置值 |

写：

| 目标 | 内容 |
| --- | --- |
| `api.storage` / `folium.storage` 的 `overhang` 键 | 一个 0–278 的整数（默认 178） |
| `win.setPosition(x, y)` | 拖动越界时把窗口夹回允许的位置，只有 x 会变 |

不写文件到别处、不发网络请求、不加载远程代码、不使用 `folium.internals`、不读播放状态。

## 权限与数据访问

`permissions` 只有一项 `filesystem.data`，因为模组用 `folium.storage` / `api.storage` 存一个
整数设置。它落在宿主本来就给每个模组准备的 `mods-data/remote-window-edge/` 里，与其他模组隔离。

要申报的非权限访问：

- **移除宿主的 `will-move` 监听**：这是功能核心。副作用是同一个窗口上其他模组注册的
  `will-move` 监听也会一起被移除；`will-move` 在 1.6 里不是公开 API，据我们所知没有模组用它。
  模组停用时会把播放器原来的规则放回去。
- **读屏幕几何**（`screen.getAllDisplays()`）：只取每块屏的 `bounds`，不读设备名、不做截图。

没有 `experimental`、没有 `embedOrigins`。

## 兼容性

- 在 **Folia 0.7.21（Folium 1.6）** 上开发。宿主 0.7.21 的 `app.asar` 里
  `remoteControlWindowGeometry.cjs`、`main.cjs` 的窗口尺寸与 `will-move` 实现已逐行核对。
- `folia: ">=0.7.21 <0.8.0"`：0.7.20（Folium 1.5）的远程控制窗口还是 428 px 宽、没有左边那块
  空闲封面区，数字不一样，所以不希望在那里加载。
- 只在 **Windows** 上起作用：宿主只在 `win32` 注册 `will-move`（别的平台的窗口管理器不允许拒绝
  移动，本来就能拖出屏幕）。其它平台上模组启动后什么都不做，也不改任何窗口。
- 只用 `registries.settingsSections`、`registries.commands`、`folium.rpc`、`folium.storage`，
  不受 1.5 → 1.6 改名影响（`params` → `settings` 两种写法都兼容）。

## 已知限制

- **依赖宿主的窗口尺寸**：602 / 594 / 174 这三个数字写在模组里（`index.cjs` 顶部常量）。
  宿主如果改了远程控制窗口的布局，拖动规则会算错，需要跟着更新模组版本。
- **靠标题和尺寸认窗口**：宿主把窗口标题改成别的、又改掉尺寸时，模组会认不出小窗，
  表现为「什么都没发生」（回到播放器原本的行为），不会报错。
- **只改拖动边界，不改窗口本身**：窗口还是 602 × 184，左边 178 px 仍然存在——空闲样式
  「展开封面」要在那里画大封面，不能真的裁掉。模组改的是「小窗能被拖到哪儿」这一条限制，
  不是窗口的形状。
- 设置改完对**已经打开的小窗**立刻生效（下一次拖动就用新值）；模组停用时会复原播放器的规则，
  但已经被拖到屏幕外的窗口不会自动移回来。

## 卸载或恢复

在「设置 → 模组」里停用或删掉模组即可。停用时模组会把播放器原本的拖动规则放回去，
小窗恢复成「拖不到屏幕左侧」。要清掉存下来的设置，删掉
`%APPDATA%\Folia\mods-data\remote-window-edge\` 整个目录。
