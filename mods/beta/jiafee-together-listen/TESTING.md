# 验证记录

## 1.4.5 切歌状态与选曲限速（2026-11-18）

先补测试复现双人准备期连续点歌缺少拦截，再经 Folium 官方 `playback.beforePlay` 加入 2.5 秒选曲间隔，准备期及本机 GO 应用完成前持续拦截；模组权威选曲只放行一次。新增 5 项锁与内部选曲联动测试，以及 4 项本机/远端抢跑、旧 GO 和歌词时序测试，完整 Node 测试 57 项通过、0 项失败；官方 0.7.28 源码检验器通过。一起听面板准备期保持已提交的曲目及进度，头像成员状态统一显示“正在切歌”，顶部提示在本机应用后自动消失。公开歌词钩子暂时隐藏目标歌词，GO 应用后刷新；原生控制条无法通过公开 API 冻结。用户于 2026-11-18 在两个保留登录资料的 Folia 0.7.28 桌面进程中测试后反馈本版通过；跨设备、更多音源和极端网络条件仍未单独验收。

## 1.4.4 切歌准备稳定性（2026-11-18）

旧实现面对“第一次暂停后宿主延迟重新播放”的模拟失败；修复后 48 项 Node 测试通过、0 项失败，包括旧中转服务 TCP 联调。官方 Folia 0.7.28 静态检查通过。真实双端切歌、慢音源和异常播放仍等待用户在保留登录资料的桌面实例中验收；没有 canplay 公开事件，不宣称消除所有准备失败。

## 1.4.3 授权边界（2026-11-17）

新增回归测试先在 1.4.2 实现上复现三项失败：局域网来源免码放行、局域网目标允许空码、网页 `Origin` 可完成 WebSocket 升级。修复后完整 Node 测试 47 项通过、0 项失败，包含原中转服务真实 TCP 联调；官方 Folia 0.7.28 源码的 `dev/folium/check.mjs` 静态检查通过。不同设备、代理线路和桌面双端连接仍需人工验收。

## 1.4.2（2026-11-17）

本地完整 Node 测试 44 项通过、0 项失败，包含原中转服务的真实 TCP 联调；官方 0.7.28 源码静态检查通过。两个既有登录目录已更新并启动官方 0.7.28；用户反馈“这次稳定很多”，不等于全面双端验收。

覆盖 seek 恢复播放、200ms + 15ms 暂停淡出、取消/拒绝准备、进度稳定、READY/GO、一次性起点校正、普通 PLAY 不归零、队列版本/重复项、TCP/WebSocket、账号资料及存储错误。真实音源是否提前出声、自然结束、快速切歌和重连仍待专项桌面日志。

仓库根目录运行：`node --test test/*.test.*`。原服务集成测试需要在相邻目录检出 `Mineradio-Jiafee-Patche`，命名为 `Jiafee-FX-Patcher`，或通过 `JIAFEE_FX_PATCHER_ROOT` 指定其绝对路径，并按其文档安装中转依赖。缺失时该项明确跳过，不能算通过；其余 43 项不需要该外部项目。

静态检查使用官方 0.7.28 源码的 `dev/folium/check.mjs`，参数传本模组绝对路径。分支基于 fork main，不能把旧宿主当成 0.7.28，也不通过修改宿主满足 API 要求。

准备仅确认暂停快照稳定，不等于 canplay。暂停淡出允许最多 0.5 秒准备偏移，GO 校正一次。不保证无声严格零进度准备，不猜测自然结束；限制详见 README。
