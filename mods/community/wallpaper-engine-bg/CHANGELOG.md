# 更新日志

## v1.2.3

正式发布前的性能整改 + 切换体验与场景脚本隔离（针对 #130 复审）。

### 主进程

- **不再有同步 IO**：扫描壁纸库、读 `project.json` / `libraryfolders.vdf`、
  `serveFile` 的 `stat` / HTML 读取全部改用 `fs.promises`；扫描加了并发上限，
  并且同一时间只扫一次，面板打开与壁纸挂载不会重复扫。
- **`scene.pkg` 不再整包读进内存**：先读目录表，再按条目只读
  `scene.json`、model / material JSON 和候选贴图区间；大包首次打开不再停住主进程。
  实测 122MB 包：整包读 + 解析约 1055ms，按需读取约 5ms；各包图层清单与原图字节
  与整包解析结果逐项一致（抽样 6 个包，含 4–19 层场景）。

### 切换体验

- **双缓冲 + 交叉淡入**：旧壁纸保留到新壁纸有内容可看，新层 240ms 淡入、
  旧层同时淡出，260ms 后销毁；连续快速切换会清掉中间层，不会越切越多。
- **大壁纸先铺静态海报**：场景壁纸加载 `scene.pkg` 时先显示原画，引擎出画后撤掉；
  视频先显示预览图，首帧就绪后撤掉；网页壁纸沿用预览图直到 iframe 加载完成。
- **选择器列表保持滚动位置**：点选壁纸后不再回到最顶端，可以接着往下挑。
- 伪随机 / 跟随桌面等自动换壁纸走同一条渲染路径，同样使用交叉淡入。
- **修复场景切换后变白/残留**：实时渲染的宿主与海报之前没挂进新层，切换时旧海报和
  画布会留在 `mediaWrap` 里，越切越多、部分场景看起来整片发白。现在它们随旧层一起销毁，
  并且引擎 canvas 一有尺寸就撤掉海报（不再依赖诊断文本来判断）。
- **修复场景切换后黑屏**：旧场景的停止函数列表是整张背景共享的，交叉淡出时旧场景清理
  会把刚创建的新引擎一起 `destroy()`，导致后面的场景停在黑/白画面上。现在每次挂载用
  自己的停止列表，旧场景只停自己的引擎。

### 场景脚本隔离

- **场景引擎和 SceneScript 搬进独立 origin 的 iframe**：每张场景一个临时端口 +
  随机路径，引擎、脚本和 scene.pkg 都只在这个 origin 内；父页面不再加载引擎，
  只通过 postMessage 送频谱、媒体、指针和暂停状态。CSP `connect-src 'self'`
  挡住外网和其他本机端口。
- **恢复场景里的歌名 / 歌手 / 时长 / 时钟 / 播放器 UI**：脚本能收到媒体属性、
  时间轴和播放状态事件；引擎出画后对文字层补发一次媒体事件，避免脚本初始化时
  错过第一帧。
- **封面先转 data URL**：父页面把 Folia 的 `file://` / 自定义协议封面读成 data URL
  再送进 iframe，避免跨源/CSP 读不到；引擎已能更新 `$mediaThumbnail`。
- **场景亮度由 iframe 上报**：跨源读不到画布像素，改成宿主每 2.5 秒采一次亮度
  发给父页面，歌词叠色仍然可用。

### 已知限制

- CSP 拦不住网页壁纸/场景 iframe 把自身 frame 导航到外部地址。它们手里只有当前曲目
  和壁纸文件，没有主服务 token、壁纸列表，风险很低。

实测（无头 Edge + 真实 DOM/CSS）：切换 200ms 时旧层 opacity 0.84、新层 0.16，
截图是两张纯色图混合出的紫色；650ms 后只剩新层。

## v1.2.2

继续按 #130 审查意见整改。v1.2.1 里「去掉 `allow-same-origin`」的做法会让
`localStorage` / `IndexedDB` 被浏览器禁用，Unity 等网页壁纸直接白屏；这一版换成
「独立 origin」隔离，壁纸照常可用，同时仍然读不到主服务和别的壁纸。

- **网页壁纸各自运行在独立的临时 origin**：主进程为每张网页壁纸单独起一个临时端口，
  只挂载它自己的目录，并带一段随机路径。壁纸页面与主服务不同端口、不同 origin，
  拿不到壁纸列表，也无法访问别的壁纸目录；卸载时端口立即关闭。
- **保留 `allow-same-origin`**：浏览器只在真实 origin 下才提供
  `localStorage` / `sessionStorage` / `IndexedDB`，去掉会让 Unity 这类壁纸白屏。
  隔离由「不同端口 + 只挂一张壁纸」保证，而不是靠 opaque origin。
- **网页壁纸加 CSP**：`connect-src 'self'`、`img-src 'self' data: blob:` 等，
  外网请求和其他本机端口一律发不出去，页面数据带不走；本地资源、
  Worker、WebAssembly 与音频响应照常。
- 主服务的随机 token 与 `Origin: null` CORS 限制保持不变；网页壁纸不再接触主服务 token。


## v1.2.1

安全审查整改（针对 #130 的审查意见），功能与 v1.2.0 一致，仅收紧执行与访问边界。

- **不再执行壁纸自带的 SceneScript**。之前引擎用 `new Function` 在 Folia 页面里求值场景包里的脚本，
  脚本可以绕过参数遮蔽拿到 `window`，等于在宿主页面执行签名范围外的代码。现在一律 `scripts: false`；
  场景仍会跑图层动画、粒子与着色器，时钟 / 文字 / 属性联动停在 `scene.json` 的快照值。
  设置里的「运行壁纸脚本」开关随之移除。
- **本机 HTTP 服务加随机路径前缀**。每次启动生成 32 位十六进制 token，接口形如
  `/<token>/i/<id>/r/...`；前缀不匹配直接 404，端口扫描读不到任何内容。
- **去掉 `Access-Control-Allow-Origin: *`**。改为只在请求 `Origin: null`（Folia 的 `file://`
  渲染端、以及沙箱 iframe）时回 `null`，普通网站不再具备跨站读取能力。
  歌词可读性的 canvas 取样仍然可用（它就是 `file://` 页面发起的）。
- **网页壁纸的 iframe 去掉 `allow-same-origin`**（v1.2.2 已改为独立 origin，见上；
  该做法会让依赖本地存储的壁纸白屏，因此没有保留）。


## v1.2.0

自首个上架版本 v1.0.0 以来的全部改动。

### 新增

- **自定义背景**：背景类型里多一个「我的文件」来源，可以直接用自己的图片和视频。
  - 图片：PNG / JPG / WebP / GIF / AVIF；视频：MP4 / M4V / WebM / MOV / MKV。
  - 「其他格式」入口可以选对话框里没列出的扩展名（BMP / SVG / ICO / TIFF、AVI / WMV / FLV / TS），
    按扩展名自动归类；能否解码取决于浏览器，解不了会在角落说明。
  - 文件通过系统对话框授权，模组只保存授权 id 与文件名，不接触真实路径；
    跨重启保留，文件被移走或删除后条目会自动清掉。
  - 自定义文件同样支持「伪随机 / 指定」两种取法。
- **跟随鼓点推拉**：替换原来的「缓慢推拉」，0–100 滑块（0 关闭，默认 30）。
  - 判定方式与自带「隐现」背景一致：全频段加权后开 0.55 次方压缩动态，
    用帧间上升量判鼓点，输出做「上升快、回落慢」的非对称平滑。
  - 图片、视频、网页、实时场景都会被带动。
- **场景加载失败的上报**
  - 实时渲染失败但兜底成功：顶部弹提示，5 秒自动收起，可直接「上报」。
  - 三层都失败：显示错误卡，可导出诊断日志、提交 Issue 或重试。
  - 日志包含阶段结果、引擎原始报错、Folia/Folium 版本、WebGL 能力、壁纸 id。
- **音频联动**
  - 每帧把 64 段实时频谱（左右各 64）喂给场景引擎。
  - 当前歌曲 / 歌手 / 专辑 / 播放状态 / 进度 / 封面同步为「正在播放」，换歌即时更新。
- **网页壁纸的 Wallpaper Engine 网页 API**
  本地服务会在返回的网页壁纸 HTML 里注入垫片，实现
  `wallpaperRegisterAudioListener` 与 `wallpaperRegisterMedia*Listener`，
  频谱与曲目通过 postMessage 推送 —— 网页类的音频响应壁纸因此也能动。
- **选择器预览不启动引擎**：背景选择器悬停时的快照只画静态图，不再为每个缩略图起 WebGL。

### 修复

- **换歌后壁纸仍显示上一首**：换歌判定原先依赖歌曲 id，而宿主给的歌曲对象没有 id，
  导致永远不刷新。改用「播放状态 + ref + 歌名 + 歌手 + 专辑 + 封面」组合签名。
- **实时渲染成功却弹错误卡**：兜底链的分支判断写反，渲染成功的场景被当成失败拆掉。
- **场景「崩溃无法打开」**：引擎已开始渲染时，`load()` 的 promise 被拒或超时也会被判定失败并销毁画面。
  现在以「渲染器是否真的启动」为准。
- **暂停时频谱条抽搐**：暂停后分析器仍吐噪声。现在暂停时不读频谱，把上一帧平滑衰减到 0，
  并对低于 0.015 的电平做噪声门限。
- **壁纸自带的 BGM 关不掉**：场景以静音装配并在加载后再压一次音量；网页壁纸不再授予
  autoplay，垫片会在壁纸自身脚本执行前把 `audio/video` 钉成静音并拦截 `play()`。
- **歌名一直停在第一首**：渲染器的文本脚本上下文缺少图层的 `size/origin/scale`，
  壁纸脚本每帧抛错、`update()` 走不到设置文字那一步。补上几何默认值后脚本能跑完。
- **三维场景整屏发蓝**：渲染器读取平行光的颜色与强度时没有解包绑定对象，太阳光被当成 0，
  只剩蓝色环境光。修复后平行光恢复；另外当环境光明显偏蓝时向亮度方向拉 85%。
- **`ctx.subscribe` 弃用警告**：改用 `ctx.onChange`（旧宿主持有回退）。

### 性能

- 重渲染加 160ms 防抖：拖滑杆、连续切换壁纸时只挂载最后一次。
- 背景选择器预览只画静态图，不创建引擎。
- 预览容器被撑成正式尺寸（或反过来）时会重新判定渲染路径。

### 兼容性

- 移除对官方预览 GIF 的兜底：场景壁纸失败时直接报错，不再放几百像素的动画预览。
- 场景壁纸不再提供「还原方式」选项，固定走「实时渲染 → 合成静态图 → 单张原画」。

### 已知限制

- **三维场景的光照只能近似**：渲染器把环境光全额乘到画面上，平行光的贡献偏弱，
  带强色环境光的场景可能与 Wallpaper Engine 里有色差。
- **场景里的着色器特效与逐帧动画无法还原**：粒子、雨、光晕等由 Wallpaper Engine 自带的
  运行时而计算，第三方只能近似。
- **部分壁纸脚本仍可能失败**：依赖渲染器未实现的脚本能力时会停在初始画面（会写进诊断日志）。
- **WebAudio 播放的 BGM 未拦截**：目前只静音 `audio/video` 元素；
  用 `AudioContext` 发声的壁纸仍可能出声。
- **纯着色器 / 悬浮窗类场景没有整屏画面**，会退回静态图或报错。
