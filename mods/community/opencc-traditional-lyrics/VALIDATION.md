# 檢查結果

日期：2026-10-27。插件版本：1.0.0。

## 驗證基準

- Folia 正式版 `v0.7.22`：`1f6d0f468f5bc81b23a8b40ad7ca96ccd4b1ecbe`。
- Folia 開發分支：`99f8468785cce03d4760d5cc80aa4eec6ec5c965`。
- Node.js 24.22.1、Vitest 4.1.11、opencc-js 1.4.2。
- 針對新插件的獨立 Vitest 設定執行；沒有宣稱跑過整個 Folia 專案的全量測試或完整應用建置。

## 結果

41 項自動測試通過，包括：

- 詞語跨逐字邊界的簡繁判斷，例如「头发发现干杯干活」→「頭髮發現乾杯幹活」。
- 中文標點、繁簡混合、英文、表情符號、Unicode 延伸漢字及相容漢字正規化。
- 原文、中文譯文、帶語言標記的其他譯文、羅馬拼音與和聲。
- 保留時間戳、音節的附加資料、ruby、聲部、段落識別及使用者分詞。
- 不修改宿主傳入的凍結物件；未變動資料保留物件身分。
- 已播放歌曲的即時套用、設定變更、命令切換、停用還原、重複啟停與取消訂閱。
- 應用尚未準備好時啟動、無歌詞歌曲、換歌及不支援介面的明確錯誤。
- 使用 Folia 真正的 `toFoliumLines`、`fromFoliumLines`、`applyLyricsTransform` 與 `rerunLyricsTransform` 測試重建，不只比對插件內部的字串。
- 使用 Folia 真正的 `createZipInstall` 安裝與覆蓋安裝，並載入安裝後的離線轉換程式。
- 使用原生 Node.js ESM 驗證：入口內容指紋改變後，會載入更新後的轉換程式。
- 檢查內附 `s2t` 與 `s2tw` 的所有字典替換均保留 Unicode code point 數量，讓原始逐字時間軸可以對回。

`node dev/folium/check.mjs opencc-traditional-lyrics` 通過；未簽章與未提供市場預覽圖只有提示，不影響本機安裝。`node --check` 語法檢查通過。

## 開發中抓到並修正的問題

| 問題 | 修正 |
| --- | --- |
| 使用 Unicode Script_Extensions 偵測日文，會把「。」「、」「「」」等中文常用標點當成日文，導致整句不轉換 | 改用文字本身的 Script 屬性，並加入標點回歸測試 |
| 逐字獨立轉換會失去「髮／發」「乾／幹」等詞語上下文 | 先整句轉換，再以 Unicode code point 對回每個時間片段 |
| 只轉 fullText 會讓逐字歌詞仍顯示簡體 | 同步處理 words、syllables、wordSegments 與 backgroundVocals |
| 停用時若先刷新、後移除處理器，畫面會繼續保留繁體 | 先取消轉換處理器，再由未轉換來源重建 |
| 入口更新後，相對匯入的轉換程式可能仍被 ESM 模組快取保留 | 將入口的內容指紋帶進 converter 模組 URL；第三方檔名固定包含版本 |
| 啟動或清理失敗可能留下事件處理器或註冊項目 | 啟動錯誤時清理，停用可重複呼叫，並確保刷新失敗時仍移除設定項目 |

以上是本插件開發與測試中發現的問題，不代表已對 Folia 全專案進行 Bug 稽核。

## 效能抽測

此執行環境載入字典約 130 ms。200 行、每行 26 字左右，包含中文譯文及逐字時間戳，連續轉換 30 次的中位數約 4.2 ms、第 95 百分位約 15.4 ms。這是開發環境的量測，不是使用者電腦的效能保證；轉換不在每一動畫影格執行。

## 尚未驗證與已知限制

- 尚未在 Windows／macOS／Linux 的完整 Electron GUI 中實際播放歌曲，也沒有使用者實機驗證。
- 不保證每一種第三方歌詞來源與其他歌詞改寫模組的組合均相容。
- 含假名／韓文的行預設整行保留。純漢字日文無法自動辨識；建議日文歌只開啟中文譯文轉換。
- 不做跨語言翻譯，不套用會改變字數的臺灣地區詞彙替換。
- OpenCC 是字典式轉換，對人名、罕見語境與有歧義的詞仍可能判斷不合預期。
- 匯出視窗不重複掛上轉換；由主視窗傳入的已轉換歌詞沿用顯示資料。影片匯出的完整 GUI 流程尚未實測。
